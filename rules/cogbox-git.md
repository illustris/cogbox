Before you use a git host that needs credentials (a private clone or fetch, a push, its API), run `cogbox-git-hosts`: it lists the git hosts this sandbox reaches through grants on its Git access tab and, where the host can tell, what is granted there, or says why it lists none; a git host reached through an injected secret instead of a grant is not listed.
For a host it lists, use a plain remote, `<base>/<group>/<project>.git` with the `base` it prints (the skill covers a host shown with `scheme=unknown`), and never put a token for that host in a URL, a header, `~/.netrc`, a credential helper or a git config; if it lists no host, do what it prints instead.
The `cogbox-git` skill has the rest; a harness that does not load skills reads `~/work/.cogbox/brain/skills/cogbox-git/SKILL.md`.
